# V2 Architecture Audit Report

## 1. V1 Summary
- **Architecture**: 100 -> 16 -> 6 -> 10 MLP. Uses ReLU activations, is strictly bias-free, and utilizes Q7.8 fixed-point arithmetic (multiplier = 256).
- **Verilog Modules & Roles**:
  - `accelerator_top.v` (Top-level wrapper, TB: `tb_accelerator_top.v`, `tb_top.v`)
  - `systolic_array.v`, `systolic_array_l1.v` (Matrix multiplication arrays, TB: `tb_array.v`, `tb_array_l2.v`, `tb_array_l3.v`)
  - `systolic_pe.v` (Processing element, TB: `tb_pe.v`, `tb_systolic_pe.v`)
  - `mac_q7_8.v` (Q7.8 sequential MAC, TB: `tb_mac_relu.v`)
  - `relu_q7_8.v`, `layer1_relu.v`, `layer_relu.v` (ReLU implementations)
  - `argmax.v` (Prediction extractor, TB: `tb_argmax.v`)
- **Python Golden Models & Hex Files**: `train_model.py` defines `VerilogNet`, exports `e2e_w1.hex`, `e2e_w2.hex`, `e2e_w3.hex`. Dedicated models for layers include `array_golden_model.py`, `layer2_golden_model.py`, `layer3_golden_model.py`.
- **Milestone History**: Progressed from `M0` to `M17` as seen in `git tag` and `git log`. 
- **Final Accuracy**: Evaluated in `v1/train_model.py` after 300 epochs of training on MNIST. M12 commit notes 93.06% accuracy. M17 describes reaching the architecture ceiling on hand-drawn generalization.

## 2. V2 Summary
- **PyTorch Model Class**: `ConvMLP_V2` defined in `v2/python_golden_model/train_v2_n0.py` and `train_and_export_all.py`.
  - Layers: Conv2d(1->4, 3x3), MaxPool2d(2x2), Conv2d(4->8, 3x3), MaxPool2d(2x2), Flatten, Linear(200->10). No 64-wide or 32-wide layers exist.
- **Exported Hex Files**: Generated by `train_and_export_all.py`.
  - `weights_q7_8.txt` (Conv1, 36 elements)
  - `conv2_weights_q7_8.txt` (Conv2, 288 elements)
  - `dense_weights_q7_8.txt` (Dense, 2000 elements mapping 200->10).
- **RTL Details**: `v2/verilog_src/v2_top.v` instantiates `conv1_array`, `maxpool_array`, `conv2_array`, `maxpool2_array`, `dense_array`, and `argmax`.
  - The hardware implements strictly 200->10. `dense_array.v` directly instantiates 10 `dense_pe.v` units. There is no `systolic_array` or 64/32-wide intermediate layers.
- **V1 Modules Reused vs Copied**:
  - `mac_q7_8.v` and `relu_q7_8.v` were physically copied. `diff` confirms they are byte-for-byte identical (337 and 194 bytes) to V1.
  - `systolic_array.v` and `layer_relu.v` were **not** copied to V2 and do not exist in the V2 RTL.
- **Test Vectors & Testbenches**: `gen_dense_vectors.py` and `gen_conv2_vectors.py` assume the true 200->10 topology. `tb_v2_top.v` tests the full pipeline but hardcodes an expected output of `7`.
- **UI Architecture**: FastAPI backend (`v2/v2_ui/backend/main.py`) receives a drawn image, downsamples to 20x20, writes it to `v2/python_golden_model/test_image_q7_8.txt`, and invokes `iverilog` to run `top_test`. It then parses outputs from snooping logic dumped in `logs/mp1_cap.txt`, `mp2_cap.txt`, and `logits_cap.txt`.
- **98.16% Accuracy**: Computed in `v2/python_golden_model/evaluate_hw_accuracy.py` over 10,000 test images using the exact 200->10 `ConvMLP_V2` model loaded with quantized Q7.8 hex weights. It uses the exact same topology as the RTL.
- **Testbench Execution**: Running `vvp top_test` yields `FAIL: Expected 7, got 9.` This is not a hardware bug, but an inconsistency in `tb_v2_top.v` which explicitly hardcodes an expectation of `7`, regardless of the contents of `test_image_q7_8.txt` generated by the UI.

## Final Conclusion
**Case applies:** (i) model and RTL both 200->10.
Both the PyTorch models (`train_v2_n0.py`, `train_and_export_all.py`, `evaluate_hw_accuracy.py`) and the corresponding Verilog (`v2_top.v`, `dense_array.v`) are perfectly aligned on the 200->10 architecture. The 98.16% accuracy claim is valid for this RTL. The `AGENTS.md` documentation simply contains outdated/incorrect architectural claims and corrupted formatting.

## 3. N11 Gap Analysis
### a. `tb_v2_top.v` Failure and MNIST Images
The testbench `tb_v2_top.v` outputs `FAIL: Expected 7, got X` because the `test_image_q7_8.txt` file is shared and overwritten by the UI. 
- Extracting the N10-tagged `test_image_q7_8.txt` and running it through the RTL yielded a prediction of `0`.
- Generating standard MNIST test images (0-9) using standard `Resize(20)` PyTorch preprocessing and running them through the RTL showed widespread failures (e.g. true label 0 yielded PyTorch pred 7 and RTL pred 1). 
- **Conclusion**: The failure in `tb_v2_top.v` is caused by the testbench hardcoding `7` as the expected answer while the UI overwrites the input image arbitrarily. Additionally, the PyTorch model (`v2_n0_model.pt`) and RTL heavily depend on a custom UI preprocessing pipeline (likely morphology/thresholding) to recognize digits, failing when standard MNIST preprocessing is applied.

### c. Bit-Exact Q7.8 Integer Emulator
**Does a bit-exact Q7.8 integer emulator of the full V2 network exist?**
No.
- `evaluate_hw_accuracy.py` loads Q7.8 fractional hex weights back into a PyTorch Float32 `ConvMLP_V2` model. It computes convolutions and dense layers using floating-point arithmetic (PyTorch `nn.Conv2d` and `nn.Linear`), meaning it does not model hardware truncation or saturation.
- `fixed_point_math.py` contains basic Q7.8 math operations (add, mul, relu) that match the hardware, and some individual layers have golden models (e.g., `conv1_layer_golden_model.py`), but there is no cohesive script that runs the entire end-to-end network in integer arithmetic.

### d. Known Issues
- `tb_v2_top.v` hardcodes the expected digit (`7`) and heavily depends on a file (`test_image_q7_8.txt`) overwritten by the UI.
- The UI backend dynamically writes `test_image_q7_8.txt` and shared logs directly into tracked folders (`python_golden_model/` and `v2_ui/backend/logs/`), which causes race conditions during concurrent requests and severely dirties the Git working tree.
